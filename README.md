# Yasno

Yasno — статически типизированный язык для вычислений и игровой логики. Компилятор выдаёт WebAssembly. Для сборки и запуска примеров достаточно Node.js. [Спецификация WebAssembly](https://www.w3.org/TR/wasm-core/)

**[Документация Yasno](guide/README.md)** · [Быстрый старт](guide/start.md) · [Справочник языка](guide/language.md) · [WebAssembly и JavaScript](guide/wasm.md) · [Рабочие примеры](examples/guide)

```text
fn main() {
    var total = 0
    for n in 1 .. 11 {
        total = total + n
    }
    print(total)
}
```

## Запуск

```powershell
node yasno.mjs run examples/primes.ys
node yasno.mjs check examples/primes.ys
node yasno.mjs build examples/primes.ys -o primes.wasm
node yasno.mjs run primes.wasm
```

Пример выводит `25`. Команда `build` без `-o` сохраняет модуль рядом с исходником. Команда `check` проверяет исходник и сгенерированный модуль.

## Калькулятор

```powershell
node examples/calculator/run.mjs "(12.5 - 2.5) * -3 + 8 / 2"
# -26
```

Калькулятор поддерживает `+`, `-`, `*`, `/`, круглые скобки, унарные знаки и дроби с точкой. Обе реализации разбирают выражение и считают в Wasm с числами `f64`. Они показывают позицию ошибки. Без аргументов калькулятор читает по одному выражению на строку. Для выхода введите `.exit`. Лимиты — 4096 символов и 64 уровня вложенных скобок. [Калькулятор на Yasno](examples/calculator/calculator.ys) · [Калькулятор на Rust](examples/calculator/calculator.rs)

Для запуска Rust установите цель `wasm32-unknown-unknown`. Если `rustc` отсутствует в `PATH`, передайте путь к нему в переменной `RUSTC`.

```powershell
rustup target add wasm32-unknown-unknown
node examples/calculator/run.mjs --rust "(12.5 - 2.5) * -3 + 8 / 2"
node bench/calculator.mjs
```

Yasno разбирает операторы обоих приоритетов в одном цикле на каждом уровне скобок и держит позицию и текущий символ в локальном значении. Компилятор сокращает повторные проверки неизменяемых ссылок и генерирует меньше переходов в циклах. Для сравнения используется прежний калькулятор на Rust, собранный с `-O`.

Замер на AMD Ryzen 5 5500, Windows x64, Node.js 26.13.0 и rustc 1.100.0. Время включает передачу текста в Wasm, разбор и вычисление. В таблице медианы трёх запусков скрипта. Каждый запуск берёт медиану 11 замеров после трёх прогревов. Длинное выражение складывает 16 выражений из короткого набора.

```powershell
node examples/voxel/serve.mjs
```

Yasno генерирует рельеф, хранит сетку размером 24 × 14 × 24, редактирует ячейки и строит список внешних граней. ## Основы языка

- `let` объявляет неизменяемое значение, `var` — изменяемое. Тип локальной переменной выводится из её начального значения. При желании его можно указать явно, например `let size: u32 = 100u32`.
- Скалярные типы — `i32`, `u32`, `i64`, `u64`, `f64` и `bool`. Целые литералы без суффикса имеют тип `i32`. Для остальных целых типов используется суффикс, например `0xffu32`. Десятичная точка или экспонента обозначают `f64`, например `2.5` или `1e-3`. Преобразования между числовыми типами явные, например `i64(size)`. Преобразование `f64` в целое отбрасывает дробную часть и останавливает выполнение, если целая часть выходит за диапазон или значение не является конечным.
- Поддерживаются функции, `if` / `else`, `while`, `for`, `break` и `continue`. У диапазона `start .. end` верхняя граница исключена. Обе границы вычисляются один раз перед циклом.
- Простые инструкции заканчиваются переводом строки. Несколько инструкций на одной строке можно разделить точкой с запятой. Комментарии начинаются с `//`.
- `fn main()` — точка входа. `print(value)` печатает скалярное значение. `export fn` публикует функцию в модуле Wasm, а `export "внешнее-имя" fn` задаёт имя экспорта явно.
- При переполнении сложения, вычитания и умножения результат оборачивается по разрядности типа. Деление на ноль и деление минимального знакового числа на `-1` завершаются ошибкой выполнения.

## Массивы и структуры

```text
struct Chunk {
    cells: [i32]
    scale: f64
}

export fn create_chunk(size: i32) -> Chunk {
    let chunk = Chunk(new [i32](size), 0.5)
    if chunk.cells.length > 0 {
        chunk.cells[0] = 7
    }
    return chunk
}
```

`new [T](n)` создаёт массив длины `n`. Длина и индекс имеют тип `i32`. Скалярные элементы начинаются с нуля, а ссылочные элементы нужно заполнить перед обращением к их полям или элементам. Выход за границы останавливает выполнение Wasm. Структуры создаются вызовом с начальными значениями полей в порядке объявления.

Массивы и структуры передаются по ссылке. Через `let` можно менять элементы массива и поля структуры. Для замены самой ссылки нужна переменная `var`. Память принадлежит экземпляру Wasm, растёт по мере необходимости до 64 МиБ и освобождается целиком вместе с экземпляром. При обновлении мира переиспользуйте буферы.

### Вызовы из приложения

Программа на Yasno объявляет импорт в формате `extern "модуль" "функция" fn имя(параметры)`. При запуске через Node.js можно передать модуль с импортами.

```powershell
node yasno.mjs run program.ys --host callbacks.mjs
```

Например, для объявления `extern "game" "notify" fn notify(count: i32)` файл `callbacks.mjs` может содержать `export default { game: { notify: count => console.log(count) } }`. В браузере тот же объект передаётся в `WebAssembly.instantiate`.

Если программа использует встроенный `print`, при прямой загрузке Wasm ей нужен импорт `yasno.print(value, code)`. Код от `0` до `5` соответствует типам `i32`, `u32`, `i64`, `u64`, `bool` и `f64`. Аргумент `value` приходит как `BigInt`, а для `f64` несёт биты числа IEEE 754.

В интерфейсе Wasm ссылка на массив или структуру — смещение `i32` в памяти этого экземпляра. Память экспортируется под именем `memory`, если программе нужны выделения или доступ к данным. У массива длина в первых четырёх байтах, элементы начинаются со смещения 8, ширина каждого элемента 4 или 8 байт по его типу. В структуре каждому полю отведено 8 байт в порядке объявления. После роста памяти представление JavaScript нужно получить заново. Ссылки передаются только в тот экземпляр, который их создал.

### Общая библиотека Wasm

```powershell
node yasno.mjs build examples/shared.ys --shared -o yasno-lib.wasm
```

`--shared` добавляет секцию `dylink.0` и собирает библиотеку скалярных функций без собственной памяти и таблицы. Другой модуль может вызвать экспортированный символ через импорт, например `extern "env" "yasno_energy" fn energy(mass: f64, velocity: f64) -> f64`. Этот режим рассчитан на вычислительные функции рядом с адаптером. Для установки в Horizon нужен адаптер, который регистрирует хуки по ABI игры и собирается в пакет `.hmod`. Сборка и загрузка такого пакета в игру здесь не проверялись. [Конвенция динамической линковки Wasm](https://github.com/WebAssembly/tool-conventions/blob/main/DynamicLinking.md) · [Загрузчик библиотек Horizon](https://github.com/horizon-rust/horizon/blob/210fdc3e6c2e002a1763d55b64e3a80494564eab/crates/horizon-mod-wasm/src/link.rs)

## Сравнение с Rust

Для воспроизведения потребуется Rust с целью `wasm32-unknown-unknown`. [Документация Rust](https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html)

```powershell
rustup target add wasm32-unknown-unknown
node bench/compare.mjs
```

Скрипт также принимает путь к `rustc` первым аргументом. Обе реализации используют одинаковые алгоритмы и аргументы. Rust собирается с `-O` и `no_std`. Обе версии выполняются в одном процессе Node.js, а скрипт проверяет совпадение результатов. В таблице медианы 11 запусков после прогрева для каждого вычисления и 7 запусков для каждой сборки.

Замер на AMD Ryzen 5 5500, Windows x64, Node.js 26.13.0 и rustc 1.100.0.

| Измерение | Yasno | Rust |
| --- | ---: | ---: |
| Простые числа до 1 000 000 | 208,65 мс | 106,38 мс |
| Контрольная сумма, 36 000 000 итераций | 53,01 мс | 59,55 мс |
| Сборка с запуском процесса | 80,27 мс | 162,56 мс |
| Размер Wasm-модуля | 261 байт | 706 байт |
