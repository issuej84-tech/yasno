# Команды и диагностика

[Документация Yasno](README.md)

Выполняйте команды из корня проекта или укажите путь к `yasno.mjs`. Путь с пробелами заключайте в кавычки.

| Команда | Действие |
| --- | --- |
| `node yasno.mjs --help` | Печатает справку. Работают также `-h` и запуск без аргументов |
| `node yasno.mjs check file.ys` | Компилирует и проверяет валидность Wasm. Файл не записывается |
| `node yasno.mjs build file.ys` | Сохраняет `file.wasm` рядом с исходником |
| `node yasno.mjs build file.ys -o out.wasm` | Сохраняет модуль по указанному пути. Папка назначения должна существовать |
| `node yasno.mjs build file.ys --shared -o lib.wasm` | Создаёт скалярную Wasm-библиотеку с секцией `dylink.0` |
| `node yasno.mjs run file.ys` | Компилирует исходник в памяти, создаёт экземпляр и вызывает `main` |
| `node yasno.mjs run file.wasm` | Загружает готовый модуль и вызывает `main` |
| `node yasno.mjs run file.ys --host host.mjs` | Берёт функции приложения из `export default` файла `host.mjs`. Можно также передать `file.wasm` |

Расширение входного файла должно соответствовать команде, выходное расширение — `.wasm`. Успешные команды завершаются кодом 0, ошибки — кодом 1. Программа с экспортами может компилироваться без `main`. В этом случае вызывайте экспортированную функцию из хоста. [WebAssembly и JavaScript](wasm.md)

## Ошибки компиляции

Диагностика показывает файл, строку, колонку, текст строки и указатель `^`. Начните с указанного места и проверьте также предыдущую строку, если ошибка связана со скобками или переносом.

```text
fn main() {
    let ratio: f64 = 2
    print(ratio)
}
```

Ожидается `f64`, а литерал `2` имеет тип `i32`. Запишите `2.0` или `f64(2)`. Если нужно присваивать переменной новое значение, объявите её через `var`. При сообщении об отсутствующем возврате проверьте, есть ли `return` для каждой ветки функции с `-> Тип`. [Правила типов и функций](language.md)

## Ошибки загрузки

Сообщение об отсутствующей функции приложения содержит пару `модуль.функция`. Сверьте её с кавычками в объявлении `extern` и добавьте функцию по тому же пути в объект `export default`, переданный через `--host`. Для вызова из JavaScript сверьте результат `WebAssembly.Module.imports(module)` с объектом импортов. [Пример с двумя импортами](wasm.md#импорты-приложения)

## Ошибки выполнения

Префикс `Ошибка выполнения` означает, что WebAssembly остановил текущий вызов. У ловушки на уровне Wasm может быть общее сообщение `unreachable`. Проверьте длину и индекс массивов, инициализацию ссылочных элементов, предел памяти, целочисленный делитель и преобразования из `f64`. `check` проверяет типы и сборку модуля. Значения, полученные в ходе исполнения, проверяются во время вызова.

## Проверки репозитория

```sh
node --test
```

Обычные тесты проверяют компиляцию и выполнение основных сценариев. Для сравнения с Rust используются отдельные скрипты. [Тесты](../tests) · [Команды для сравнения](../README.md#сравнение-с-rust)
